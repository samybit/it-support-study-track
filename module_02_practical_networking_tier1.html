LESSON 01 OF 08 • NETWORK DIAGNOSTIC MINDSET

The Network Triage Ladder: How Tier-1 Isolates "No Internet"

Users call almost every network issue "The internet is down." As a web developer, you already know HTTP requests fail for completely different reasons (DNS failure, connection timeout, firewall block, or offline client). At the Service Desk, you test four sequential hops outward from the laptop so you pinpoint the exact break point in under 60 seconds.

ACRONYM DECODER

What Every Network Term in Lesson 01 Stands For

NIC = Network Interface Card
The physical Ethernet port or Wi-Fi chip inside the PC.
LAN / WAN
Local Area Network (office) vs. Wide Area Network (internet/branches).
ICMP = Internet Control Message Protocol
The diagnostic echo protocol used by ping and tracert.
Loopback = 127.0.0.1
Reserved self-test IP (localhost) proving Windows' own TCP/IP stack works.
Default Gateway = Local Router IP
The office router door that forwards traffic outside your local LAN.
ISP = Internet Service Provider
External telecom carrier (e.g., WE, Orange, Vodafone) supplying the WAN link.
BEGINNER MENTAL MODEL • WHAT HAPPENS WHEN YOU OPEN A WEBSITE?

When an employee types portal.aboughaly.com into Chrome, four invisible steps happen in milliseconds: (1) Physical Link: The laptop's NIC has an active Wi-Fi or Ethernet signal. (2) Local Identity (IP + DHCP): The laptop has a valid office IPv4 address (not 169.254.x.x). (3) Name Lookup (DNS): Windows asks the DNS server to translate portal.aboughaly.com into a numeric IP address. (4) Routing (Default Gateway): Windows sends packets to the Default Gateway router, which forwards them across the internet to the server. If any single link in that 4-step chain breaks, the browser shows the exact same vague "This site can't be reached" page!

The 4-Step Ping Isolation Ladder (Inside → Out)

Memorize This Sequence

Run these four ping targets in order from closest (inside the PC) to farthest (public internet name). The first step that fails tells you the exact layer to fix:

STEP 01 • SELF / STACK
ping 127.0.0.1

Tests the PC's own TCP/IP software stack.
If fails: Windows TCP/IP / Winsock stack is corrupted (netsh int ip reset).

STEP 02 • LOCAL LAN / ROUTER
ping <Gateway IP>

Tests cable/Wi-Fi + local IP to your Default Gateway (e.g., 192.168.1.1).
If fails: Cable unplugged, wrong Wi-Fi, or 169.254.x.x APIPA IP.

STEP 03 • EXTERNAL IP
ping 8.8.8.8

Tests raw internet routing beyond your router (Google Public DNS IP) without using DNS.
If fails: Office ISP WAN outage or firewall blocking outbound traffic.

STEP 04 • NAME RESOLUTION
ping google.com

Tests whether DNS translates names to IPs.
If Step 3 works but Step 4 fails: Points directly to DNS / name resolution! Raw IP routing works, so check DNS server, cache, hosts file, or Port 53.

FIELD CAVEAT ON PING: Some corporate firewalls or cloud websites block inbound ICMP Echo Requests (returning Request timed out even when HTTPS port 443 works). Always verify with a known ICMP-friendly target (8.8.8.8 or your Default Gateway) or test the TCP port directly with Test-NetConnection.

LESSON 02 OF 08 • CORE ADDRESSING & ROUTING

IPv4 Addressing, Subnet Masks & Default Gateway

For Tier-1 Service Desk roles, you do not need to calculate binary subnet math in your head. You need to understand what the three core IPv4 numbers do, recognize private vs. broken IP ranges on sight, and spot a misconfigured Subnet Mask or Default Gateway immediately.

ACRONYM DECODER

What Every Addressing Term in Lesson 02 Stands For

IPv4 / IPv6
Internet Protocol version 4 (32-bit, 192.168.1.50) & version 6 (128-bit hex).
Octet = 8-bit number (0–255)
Each of the 4 dot-separated numbers in an IPv4 address (10.20.30.40).
CIDR = Classless Inter-Domain Routing
Slash shorthand for subnet mask (e.g., /24 = 255.255.255.0).
MAC = Media Access Control
Permanent hardware address burned into the NIC (e.g., A4-83-E7-12-9B-01).
ARP = Address Resolution Protocol
Maps a local IPv4 address to its physical MAC address on the LAN switch.
NAT = Network Address Translation
Your router translating private office IPs into one public internet IP.

1. The Three Numbers Every Networked PC Needs

1. IPv4 ADDRESS

Your Device's Street Address

Four numbers (0–255) separated by dots, e.g. 192.168.10.45. Every active device on the same network must have a unique IPv4 address—two PCs with the same IP trigger an IP conflict.
Fix: Run ipconfig /release then /renew, or find the other device and move its static IP outside the DHCP pool.

2. SUBNET MASK

Network Part vs. Host Part

Tells Windows which portion of the IP is your office network (street) and which portion is your specific device (house number). In 255.255.255.0 (/24), the first 3 numbers (192.168.10) are the network and the last (.45) is the host.

3. DEFAULT GATEWAY

The Exit Door Off Your LAN

The IP address of your local router (often .1 or .254, e.g. 192.168.10.1). If a destination IP is on your same subnet, Windows talks directly; if it's outside, Windows sends packets to the Default Gateway.

CLASSIC TIER-1 SYMPTOM OF A MISSING DEFAULT GATEWAY:
A user can open internal file shares (\\FS01\Finance) and ping coworkers on the same floor, but cannot reach any external website or cloud M365 app. Cause: someone entered a manual static IP and left the Default Gateway blank (or typed a gateway IP on the wrong subnet)!

2. IPv4 Ranges You Must Recognize Immediately

Instant Visual Triage
Range / CIDR Category What Seeing It in ipconfig Tells You
10.0.0.0 – 10.255.255.255 (/8) Private (RFC 1918) Standard enterprise corporate office, VPN, or branch VLAN IP. Healthy internal IP.
172.16.0.0 – 172.31.255.255 (/12) Private (RFC 1918) Medium/enterprise internal LAN, Docker/WSL virtual switches, or corporate VPN pool.
192.168.0.0 – 192.168.255.255 (/16) Private (RFC 1918) Small office or employee home Wi-Fi router (e.g., 192.168.1.x). Healthy local IP.
169.254.0.0 – 169.254.255.255 (/16) APIPA (Broken DHCP) RED FLAG! PC failed to reach a DHCP server and self-assigned a link-local IP. Cannot route to internet or servers.
127.0.0.0 – 127.255.255.255 (127.0.0.1) Loopback Points back to the local PC itself (localhost). Used for testing the local TCP/IP stack.

IPv6 One-Liner: Windows adapters also display a 128-bit hex IPv6 address (fe80::... link-local is normal by default); if web apps stall despite healthy IPv4, broken upstream IPv6 routing or VPN IPv6 handling may be the culprit.

LESSON 03 OF 08 • AUTOMATIC IP ASSIGNMENT

DHCP & APIPA (169.254.x.x) Failures

Typing IP addresses manually on 500 office laptops would be impossible. Instead, a DHCP Server hands out IP settings automatically every time a PC connects—until a cable, switch port, or full IP pool breaks that handshake and leaves the PC stranded on 169.254.x.x.

ACRONYM DECODER

What Every DHCP Abbreviation in Lesson 03 Stands For

DHCP
Dynamic Host Configuration Protocol (auto-assigns IP, Mask, Gateway & DNS).
DORA
Discover → Offer → Request → Acknowledge (4-step DHCP handshake).
APIPA
Automatic Private IP Addressing (169.254.x.x fallback when DHCP fails).
DHCP Lease
Temporary rental timer (e.g., 8 hours or 8 days) before the IP returns to the pool.
DHCP Scope / Pool
The range of available IPs a DHCP server can hand out (e.g., .50 to .200).
DHCP Reservation
Permanently locks a specific IP to a printer/server's MAC address via DHCP.

1. How DHCP Works: The 4-Step DORA Handshake

When a laptop plugs into an Ethernet jack or joins Wi-Fi, it has no IP address yet—so it shouts a broadcast across the local LAN (Ports UDP 67/68):

D • DISCOVER (Client → All)

"I have no IP! Are there any DHCP servers on this network?"

O • OFFER (Server → Client)

"I'm the DHCP server—you can lease 10.10.20.84 with mask, gateway & DNS."

R • REQUEST (Client → Server)

"Thanks, I officially accept 10.10.20.84!"

A • ACKNOWLEDGE (Server → Client)

"Confirmed! Logged in my lease table for 8 days."

FIELD TRAP • APIPA

2. Why Does 169.254.x.x Appear?

If Windows sends DHCP Discover packets and gets zero replies, Windows refuses to leave the network card blank—instead, APIPA (Automatic Private IP Addressing) picks a random IP between 169.254.0.1 and 169.254.255.254 with subnet mask 255.255.0.0 and no Default Gateway.

Top 4 Causes of 169.254.x.x
  • Damaged Ethernet patch cable, bad dock port, or dead wall jack
  • Switch port is disabled or assigned to a dead/unrouted VLAN
  • DHCP Scope Exhaustion: Every IP in the office pool is leased out (classic in busy conference rooms or guest Wi-Fi!)
  • Windows DHCP Client service (Dhcp in services.msc) is stopped
Tier-1 Fix Sequence
  • Run ipconfig /release followed by ipconfig /renew
  • Check NIC link lights & swap Ethernet cable / test on Wi-Fi to isolate laptop vs. wall port
  • Verify ncpa.cpl → IPv4 Properties is set to Obtain an IP address automatically
  • If multiple users on the same floor get 169.254.x.x, escalate to NetOps (DHCP scope full or switch uplink down)
LESSON 04 OF 08 • NAME-TO-IP TRANSLATION

DNS (Domain Name System) & Name Resolution

Computers route packets using IP addresses, not domain names. DNS is the distributed phonebook that translates outlook.office.com or FS01.corp.local into an IP address—and it is responsible for roughly half of all "the website won't load" tickets.

ACRONYM DECODER

What Every DNS Term in Lesson 04 Stands For

DNS = Domain Name System
Translates human hostnames into IP addresses (Port 53).
FQDN = Fully Qualified Domain Name
Complete exact address: fs01.aboughaly.local.
A / CNAME / MX
Address (Name→IPv4) • Canonical Name (Alias) • Mail Exchanger.
TTL = Time To Live
Seconds Windows caches a DNS answer before asking the server again.
HOSTS File
Local override text file at C:\Windows\System32\drivers\etc\hosts.
NXDOMAIN = Non-Existent Domain
DNS server reply meaning "No record exists for that name."

1. How Windows Resolves a Name (3-Step Lookup Chain)

STEP 1 • LOCAL DNS CACHE

Windows checks its in-memory DNS Resolver Cache first. If an IT admin just moved a server to a new IP, Windows still remembers the old cached IP until its TTL expires—or until you run ipconfig /flushdns.

STEP 2 • LOCAL HOSTS FILE

Next, Windows checks C:\Windows\System32\drivers\etc\hosts. Developers or old installers sometimes hardcode entries here, overriding real DNS and breaking migrated apps.

STEP 3 • CONFIGURED DNS SERVER

Finally, Windows sends a DNS query (Port 53) to the DNS Server IP listed in ipconfig /all (usually your on-prem Domain Controller in an office, or your router/ISP at home).

CRITICAL ENTERPRISE TRAP

Never Permanently Set a Work PC's DNS to 8.8.8.8!

In a home setup, changing DNS to Google (8.8.8.8) or Cloudflare (1.1.1.1) is harmless. In a corporate Active Directory office, it breaks internal resources! Google's public DNS knows google.com, but it has zero knowledge of internal company names like \\FS01\Finance, intranet.company.local, or your Active Directory Domain Controller.

How to test DNS safely without changing adapter settings: Run nslookup portal.company.com 8.8.8.8 in Command Prompt. That queries 8.8.8.8 for a single one-off test while leaving the laptop's corporate DNS settings untouched!
LESSON 05 OF 08 • MEDIA & REMOTE CONNECTIVITY

LAN vs. Wi-Fi & Corporate VPN Awareness

Whether an employee sits at an office docking station over copper Ethernet, roams between floor Access Points on Wi-Fi, or works from home over a VPN tunnel, each connection medium has its own signature failure modes.

ACRONYM DECODER

What Every Connectivity Term in Lesson 05 Stands For

SSID / AP
Service Set IDentifier (Wi-Fi network name) • Access Point.
WPA2 / WPA3 / 802.1X
Wi-Fi Protected Access security • Enterprise username/cert login.
PoE / RJ45
Power over Ethernet (powers desk phones/APs) • Standard Ethernet plug.
VPN = Virtual Private Network
Encrypted tunnel connecting a remote laptop into the office LAN.
Split vs. Full Tunnel
Split: only office traffic uses VPN. Full: all internet routes via office.
Captive Portal
Hotel/airport Wi-Fi login webpage that blocks VPN/HTTPS until accepted.

1. Wired LAN (Ethernet) vs. Enterprise Wi-Fi

WIRED LAN (Cat5e / Cat6 Ethernet)
  • Link Lights: Solid green/amber LED = physical electrical link to the switch; blinking LED = active data frames. Both LEDs dark = unplugged cable, dead wall jack, or disabled switch port.
  • Docking Station Trap: USB-C docks contain their own internal USB Ethernet NIC. If wired drops on a dock, test unplugging/re-seating the USB-C dock cable or plugging Ethernet directly into the laptop.
  • Speed Negotiation: Check ncpa.cpl → Status: healthy office links negotiate 1.0 Gbps (or 100 Mbps on older wall runs). 10 Mbps indicates a damaged cable pair.
WIRELESS LAN (2.4 GHz vs. 5 GHz / 6 GHz)
  • 2.4 GHz: Travels farther through concrete walls, but slower and heavily congested by neighboring routers and Bluetooth.
  • 5 GHz / 6 GHz: Much faster throughput with less interference, but shorter range—drops off behind thick office walls.
  • Password Change Wi-Fi Lockout: On corporate WPA2/WPA3-Enterprise Wi-Fi (which authenticates using the employee's AD username/password), resetting a user's AD password often causes Windows to spam the old cached Wi-Fi password and lock their AD account! Right-click SSID → Forget and reconnect.

2. Corporate VPN Awareness (Remote Work Triage)

FortiClient • GlobalProtect • Cisco AnyConnect

When an employee works from home, their laptop is on a public residential ISP network—outside the office firewall. Connecting the VPN client builds an encrypted tunnel back into the corporate network and assigns the laptop a virtual corporate IP address.

1. Home Internet Must Work First A VPN rides on top of the user's home Wi-Fi or hotspot. If their home Wi-Fi has no internet or is stuck behind a hotel Captive Portal login page, VPN will always fail at 0–10%.
2. "Z: Drive Won't Open From Home" Classic ticket! On-premises file shares (\\FS01\Finance), internal ERP portals, and RDP to office desktops are blocked from the public internet—connect VPN first, then refresh Z:\.
3. VPN Connects, Websites Slow/Blocked In a Full-Tunnel VPN, all YouTube/web traffic routes through the office firewall (which may throttle or block streaming). In a Split-Tunnel VPN, only internal corporate subnets go through VPN while general web traffic goes straight out the user's home ISP.
LESSON 06 OF 08 • NETWORK PORTS & FIREWALLS

Everyday Network Ports & Windows Firewall Triage

If an IP address is the street address of an office building, a Port Number (0–65535) is the exact suite number inside that building telling the server which application should handle the incoming request.

ACRONYM DECODER

What Every Port & Protocol Acronym in Lesson 06 Stands For

TCP = Transmission Control Protocol
Reliable, acknowledged delivery (3-way handshake: SYN, SYN-ACK, ACK).
UDP = User Datagram Protocol
Fast, connectionless delivery used for DNS lookups, DHCP & Teams voice/video.
HTTP / HTTPS
Hypertext Transfer Protocol (Port 80) & Secure TLS encrypted (Port 443).
RDP = Remote Desktop Protocol
Microsoft graphical remote control protocol (Port 3389).
SMB = Server Message Block
Windows network file sharing (\\FS01\Share) & printing (Port 445).
SSH = Secure Shell
Encrypted command-line login for Linux servers, switches & firewalls (Port 22).

1. The 6 Everyday Ports Every Tier-1 Tech Must Know Cold

Interview Favorite
Port Protocol Transport Real-World Service Desk Relevance
22 SSH TCP Encrypted CLI administration for Linux servers, network switches, and SFTP file transfers.
53 DNS UDP / TCP Domain Name System lookups (UDP for standard queries; TCP for large responses/zone transfers).
80 HTTP TCP Unencrypted web traffic (usually redirects to 443, or triggers hotel/airport Wi-Fi captive portals).
443 HTTPS TCP Encrypted web traffic—Microsoft 365, Teams, webmail, SSL VPN gateways, and modern SaaS apps.
445 SMB TCP Windows File & Printer Sharing (\\FS01\Finance). Often blocked by ISPs over public internet—requires VPN!
3389 RDP TCP / UDP Windows Remote Desktop connection to jump hosts, servers, or office workstations.
# Test if a specific TCP port is reachable in PowerShell (when ping/ICMP is blocked!):
Test-NetConnection -ComputerName google.com -Port 443
Look at the final line: TcpTestSucceeded : True proves end-to-end TCP reachability on Port 443 even if ICMP ping is blocked. Replace google.com and 443 with FS01 and 445 to prove whether SMB file sharing is open or blocked by a firewall!

2. Windows Defender Firewall Profiles (wf.msc)

Windows applies three separate firewall rule sets depending on which network profile your adapter detects: Domain (authenticated to corporate Active Directory), Private (trusted home/small office), and Public (cafes, airports, untrusted networks—strictest blocking).

COMMON DESK FIX: A small-office workstation without Active Directory suddenly stops sharing a USB printer or folder after a router swap. Reason: Windows classified the new router as a Public network, blocking inbound SMB/discovery. Switch the connection profile back to Private in Settings → Network & internet → Properties.
LESSON 07 OF 08 • COMMAND-LINE TOOLKIT

Diagnostic CLI Commands Deep-Dive

GUIs hide details behind five clicks; Command Prompt (cmd) gives you raw ground-truth proof in two seconds. Here is every command from the Tier-1 syllabus, what flags matter, and how to read the output like an engineer.

ACRONYM DECODER

What Every CLI Output Term in Lesson 07 Stands For

RTT (time=14ms)
Round-Trip Time in milliseconds for a packet to go and return.
Hop = One Router Step
Each router a packet passes through in tracert (max 30 hops).
netstat -ano
Network Statistics: -a all ports, -n numeric IPs, -o owning PID.
1. ipconfig /all — Complete Adapter & Lease Inspection
ipconfig /all
Plain ipconfig only shows IPv4, Subnet Mask, and Default Gateway. Adding /all reveals five critical extra fields: Physical Address (MAC), DHCP Enabled (Yes/No), DHCP Server IP, Lease Obtained/Expires, and DNS Servers.
2. ipconfig /release && ipconfig /renew — Refresh DHCP Lease Safely
ipconfig /release && ipconfig /renew
/release drops the current IP back to 0.0.0.0; /renew broadcasts a fresh DHCP Discover/Request.
REMOTE SUPPORT WARNING: Never run ipconfig /release alone while connected over Quick Assist, AnyDesk, or RDP—dropping the IP disconnects your remote session before you can type /renew! Always chain them with &&.
3. ipconfig /flushdns — Clear Stale Local DNS Cache
ipconfig /flushdns
Purges cached name-to-IP records from Windows' DNS Resolver Cache so the next request fetches fresh DNS records from the server.
4. ping & ping -t — Reachability, Packet Loss & Jitter
ping 8.8.8.8   |   ping -t 8.8.8.8
Default ping sends 4 ICMP echo packets. Adding -t pings continuously (press Ctrl + C to stop and print packet loss statistics)—ideal for catching intermittent Wi-Fi drops or latency spikes during Teams calls.
5. tracert — Hop-by-Hop Path Diagnosis
tracert -d 8.8.8.8
Lists every router hop between the PC and the destination (-d skips reverse DNS lookups so it finishes 3x faster). If Hop 1 (Default Gateway) replies in 1ms and Hop 3+ times out (* * *), it points to the ISP / upstream path rather than your office LAN—though note that some routers simply ignore or deprioritize tracert probes (if later hops reply, intermediate * * * timeouts are normal).
6. nslookup — Direct DNS Server Query
nslookup google.com   |   nslookup google.com 8.8.8.8
Shows which DNS server answered (Server: ...) and what IP it returned (Address: ...). Comparing your default DNS server against 8.8.8.8 proves immediately whether your local DNS server is failing.
7. Bonus Tools — netstat, arp & displaydns
netstat -ano   |   arp -a   |   ipconfig /displaydns
netstat -ano lists every open port and active connection with the owning PID. Use it to find which process is using a port (for example, an app that won't start because port 443 is taken), then match the PID in Task Manager → Details. Add | findstr :443 to filter one port.

arp -a shows the table of IP-to-MAC pairs your PC has learned on the LAN. Use it to spot an IP conflict: two different IPs are fine, but the same IP showing a MAC that doesn't match the expected device means another machine is using that address.

ipconfig /displaydns prints the cached DNS records Windows is holding. If a name resolves to an old IP after a server move, you'll see it here, and ipconfig /flushdns clears it.
LESSON 08 OF 08 • FIELD OPS • REPAIR & ESCALATION

Windows Network Stack Reset, Proxy Traps & Escalation SOP

Sometimes the office network is completely healthy, yet one laptop shows "Connected, no internet" after a crashed VPN client or bad update. Know how to catch hidden proxy overrides, reset the Windows network stack cleanly, and write a rock-solid Tier-2 escalation note when an outage is genuinely upstream.

1. Single-PC "No Internet" Fixes (Quick Toggles, Proxy & Stack Reset)

FIRST-LINE NON-REBOOT FIXES (TRY THESE BEFORE NETSH RESET)
  • Disable & Re-enable Adapter (ncpa.cpl): Right-click Wi-Fi or Ethernet → Disable, wait 5 seconds, then Enable to clear a wedged NIC or DHCP state without rebooting (local hands-on only—never disable the active adapter during a remote session!).
  • Windows Network Troubleshooter: Run Settings → Network & internet → Diagnose network problems (or right-click the taskbar network icon) to automatically detect and reset broken adapter, DHCP, or DNS bindings in seconds.
Check Stuck Proxy (inetcpl.cpl) Run inetcpl.cpl (Win + R) → Connections → LAN settings. Crashed VPN clients, security agents, or adware often leave "Use a proxy server for your LAN" checked pointing to 127.0.0.1:8080—which hijacks all browser traffic while ping 8.8.8.8 still works!
Windows Network Reset (GUI Alternative) In Settings → Network & internet → Advanced network settings → Network reset, Windows reinstalls all network adapters back to defaults and reboots in 5 minutes (note: requires re-entering Wi-Fi passwords).
# Full Windows TCP/IP & Winsock Stack Reset in Admin CMD (Requires Restart!):
netsh winsock reset
netsh int ip reset
ipconfig /flushdns
What each command repairs: netsh winsock reset rebuilds the Windows Sockets catalog (used by every app to open network connections); netsh int ip reset rewrites the TCP/IP registry keys back to clean defaults. Always restart the PC afterward so the clean stack loads.
ESCALATION HANDOFF SOP

2. When to Escalate to Network / Infrastructure & What to Attach

Escalate immediately when diagnostics prove the fault is outside a single workstation: multiple users on the same switch/floor offline, DHCP scope exhausted, ping 8.8.8.8 failing at the office ISP gateway across all PCs, or an enterprise DNS/file server unreachable by all departments.

# Copy-Ready Tier-2 Network Escalation Template:
Scope: 12 users on Floor 2 East Wing (Switch Closet B, Wall Ports 2B-14 to 2B-25)
Symptom: Wired Ethernet adapters pull 169.254.x.x (APIPA); Wi-Fi on same floor works.
Tests Run:
- ipconfig /all: IPv4 169.254.88.14, DHCP Enabled: Yes, DHCP Server: blank, MAC: A4-83-E7-12-9B-01
- ipconfig /release && /renew: Timed out ("unable to contact your DHCP server")
- Swap test: Verified with known-good patch cable and 2nd laptop on port 2B-14 (same 169.254.x.x)
Request: Check VLAN / DHCP relay configuration on Floor 2 East switch uplink.
